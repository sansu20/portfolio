Computer Vision Analysis

The Raspberry Pi reads the board from underneath and tracks every move from the starting position.

How it works

The camera under the board looks up through a hole for each square. For every square, the software checks the color of the piece base: red, yellow, or empty. Comparing the board before and after a move shows which piece moved and where, so the game state can be tracked from the starting position without needing every piece to be a different color.

Credit: I wrote the detection pipeline and move tracking. My partner built the board and camera housing it runs on, and we tested and debugged together.

The program prints each side's occupied squares: 16 red and 15 yellow on this board.

Major complication: lighting

The first version misidentified about 10% of pieces. The cause was lighting. Changing light conditions shifted the RGB values heavily, so the same red base could read as a different color from one moment to the next.

The fix

ChangeWhy it helps
RGB to HSVHSV separates the color itself (hue) from brightness, so a change in lighting mostly moves brightness and leaves hue stable.
Median pixel value over each holeA single glare spot or shadow no longer decides the reading for a square.
Most common reading over several framesA one-frame flicker or misread gets outvoted by the other frames.
Result: errors dropped from about 10% to close to zero.

Current status

Detection works reliably on the test board. The remaining work is honing the full pipeline, calibrating board positions, and integrating vision with the arm and the game algorithm so the robot can play complete games.
