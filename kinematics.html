Inverse Kinematics

The arm is told a chess square. Inverse kinematics turns that square into the two joint angles that put the magnet over it.

My part: I wrote all of the software, including this. My partner built the arm and board it controls, and we calibrated them together.

The problem

A chess move is described as squares, like "E2 to E4". The arm is controlled by motor angles. Something has to translate between the two. That translation is inverse kinematics: given where the end of the arm should be, find the joint angles that put it there.

The math for a two-link arm

A SCARA arm moves in a flat plane with two rotating links, so its geometry reduces to a triangle. For a target at (x, y), the distance from the base is r² = x² + y². The law of cosines gives the elbow angle, and the shoulder angle follows from the target direction minus an offset caused by the second link.

# Inputs: target x, y; link lengths L1, L2
# Output: shoulder angle theta1, elbow angle theta2

r2 = x*x + y*y
cos_elbow = (r2 - L1*L1 - L2*L2) / (2 * L1 * L2)

if abs(cos_elbow) > 1:
    reject_move()            # target is out of reach

theta2 = acos(cos_elbow)     # elbow angle (pick one solution, see below)
theta1 = atan2(y, x) - atan2(L2 * sin(theta2), L1 + L2 * cos(theta2))

Two solutions

Most targets can be reached with the elbow bent either way. The code picks one configuration and sticks with it, so the arm never flips between the two in the middle of a game.

Out-of-reach targets

If the cosine value falls outside the range −1 to 1, the target is farther than the arm can stretch or closer than it can fold. The move is rejected instead of sending the motors somewhere impossible.

Calibration and feedback

The math assumes perfect link lengths and a known zero position. Real hardware is never that clean, which is why the belt rebuild mattered so much. With gears, the motor position wandered by about 2 degrees and there was no repeatable zero, so correct angles still landed in the wrong place. With tensioned timing belts the error dropped to nearly zero, and calibration became a matter of adjusting the stored board positions instead of fighting the hardware.

Ongoing work: calibrating board positions and arm movement is one of the main remaining tasks before full playability.
